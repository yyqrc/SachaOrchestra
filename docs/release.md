# Sacha Orchestra 发版与安装指南

> 本指南只供插件开发使用，不进入发布插件。用于明确的发版、安装请求，以及本流程的维护。

## 默认发版

“发版”和“快速发版”使用同一路径：交付已经完成的改动，复用仍有效的测试和评审；只对新增未验证差异、失效证据或已知问题补验。发布动作本身不触发重新开发、全量 Review、回归、构建、安装或运行场景。

- EVOLUTION.md 保存发布版本、待发布范围与破坏性边界；三个部署清单保存源码版本，annotated tag 标识已发布版本。README 只在入口、用法或其现有信息确实变化时更新，不为每次发版补一份总结。
- 明确发版请求授权当前确定范围的 commit、annotated tag 和 push；不授权安装、刷新缓存、市场注册、外部服务修改或 Runtime 验收。用户给出版本时使用该版本；未给出时沿用 patch 递增默认，存在未决定的破坏性版本边界时只澄清该决定。
- 保护范围外 working/untracked 内容，不执行 stash、reset、clean、rebase、强制 checkout 或历史改写。发布范围或目标不唯一时，先核实能自行确认的事实。

## 准备与已有证据

1. 从当前任务、已批准 Spec、实施报告和明确提交确定待发范围，读取必要的原始测试结果与独立评审结论。核对它们仍适用于实际发布内容、验收输入和环境；不重新恢复完整实施过程。
2. 已验证内容、验收输入和证据边界未变时直接复用。版本号、发布状态和纯发布说明变化只核对其准确性，不因 staged tree 改变就重跑测试或新增独立评审。
3. 有新增未验证的行为差异或失效证据时，只补对应检查；原评审后的变化确实影响裁决时，只评审该差异与直接影响。已有明确失败或必需检查缺失不能当作“快速”理由跳过。真实场景是否需要仍按根 AGENTS.md 的触发条件判断。
4. 更新必要的版本与发布信息，精确暂存本次发布内容。需要新增评审与测试时，两者在输入独立且无冲突的前提下并行；共享同一输入的命令结果直接复用，失败或范围变化只处理受影响部分。

`release.py prepare` 是按需补验工具，不是发版必经步骤。只有本次候选确实需要它选择的检查时才运行；仅需个别已有测试时，使用现有 staged_snapshot 导出的同一暂存树隔离快照执行相应命令并保留 tree 与原始结果，不用包含范围外改动的工作区结果替代候选证据，也不为了调用 prepare 重跑已经有效的检查。

```powershell
python -B scripts/release.py prepare --version <version> --candidate-path <path> [--candidate-path <path> ...]
```

prepare 按暂存文件选择检查并导出隔离快照，它不自动复用过去测试结果。DSH 路径会触发配套包验证及 pnpm verify；主插件发版不自动等于独立 DSH 包的重新构建或安装，只有对应交付确需补证且前置满足时才执行。缺少依赖时不得借验证自动安装。

## 提交与发布

必要准备已完成后，使用现有发布入口：

```powershell
python -B scripts/release.py publish --version <version> --review reused|accepted|not-required --message <commit-message> --candidate-path <path> [--candidate-path <path> ...]
```

- `--candidate-path` 必须精确匹配暂存文件；冲突、范围不一致或这些文件暂存后又变化时停止受影响发布。review 参数显式记录 reused（复用已有评审）、accepted（本次评审通过）或 not-required（按现行规则无需正式评审）；不能把无需评审写成已通过，也不能用参数替代实际证据。
- 执行前核对版本与发布信息，按已确定版本更新 EVOLUTION.md 并暂存；tag 成功前不宣称版本已经发布。脚本执行 candidate 机器身份检查、commit、annotated tag、release 身份检查、原子 push 和远端核对，不运行回归测试或独立 Review。
- publish 返回 status=pass，并给出 commit、tree、branch、tag、remote 和 remote_verified=true 后直接交付。只再用一次 cprobe 检查范围外工作区边界；不例行重查 manifest、HEAD/tag、远端或插件列表。
- 失败时根据原始错误与已完成阶段恢复，不盲目重跑产生 commit、tag 或 push 的动作。脚本不可用时只对缺少的机械步骤使用原生 Git 与现有身份校验入口，不重新执行全流程。
- 报告实际发布版本、提交和远端结果，以及明确失败、风险和未满足的必需条件。没有触发的安装或运行检查不形成欠账；耗时使用现有脚本输出，不凭感觉承诺固定总时长。

## 安装与缓存核对

安装、重装、刷新、市场注册或 cache parity 需要对应明确授权；来源直连和版本变化本身不触发安装。

1. 需要安装证据时核对当前插件 PATH、版本和目标；PATH 指向仓库发布 root 表示源码直连，不等于新安装或运行通过。市场名称使用当前 read_marketplace_name.py 读取，不根据目录名猜测。
2. 目标、版本与授权明确后，按适配器或现有 `release.py install --version <version>` 执行。相同决定不重复询问，不改安装缓存、系统 PATH 或应用权限，不添加 cachebuster。
3. 安装前关闭本次发布创建且已经终态、可关闭的辅助代理。拒绝访问或缓存已创建但登记未完成时保留状态与错误；解除占用后用同一 CLI 恢复，不手工删除或覆盖缓存。
4. 安装结果只证明对应安装、发现和来源/缓存一致性；实际行为需要相应运行证据。发布成功不能代替安装后的发现和运行结果。
