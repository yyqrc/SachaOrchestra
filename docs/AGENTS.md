# Sacha Orchestra 开发文档规则

> 文档身份：插件开发使用；不进入发布插件。

## 身份与负责文件

- `CONTEXT.md` 是开发文档侧提炼术语与规则的统一入口，并负责开发专用术语；它保存插件内共享术语的开发侧同步定义，但不复制入口、角色、批准、迁移或协调动作。
- `integrations/**` 保存当前能力提供方、项目接入和其他开发接入指南；指南只解释开发者如何提供、维护和核查接入，不成为安装后的依赖。
- `release.md` 保存用户明确要求快速发版、普通发版或安装时使用的开发期操作指南；当前版本身份仍由 [`EVOLUTION.md`](../EVOLUTION.md) 负责，机械执行仍由 [`scripts/release.py`](../scripts/release.py) 负责。
- `plan/**` 保存具名任务的实施规格（Spec）、实施报告（Execution Report）和评审记录（Review Artifact）；它们只服务对应任务、恢复或历史取证，不定义当前产品流程、安装后流转或版本状态。

## 读取与维护

- 修改提炼术语或开发规则时，开发者或评审者先读 `CONTEXT.md`，再按[根 `AGENTS.md`](../AGENTS.md) 核对 [`PLUGIN_DESIGN.md`](../PLUGIN_DESIGN.md)、插件内负责文件和实际使用方；不得从历史任务工作记录恢复当前机制。
- 修改能力提供方、绑定或项目接入时，开发者或评审者只读 `integrations/` 中的目标指南及其具名负责文件和使用方；不得遍历无关提供方或历史计划。
- 用户明确要求快速发版、普通发版或安装时，发布执行者读取 `release.md`、[`EVOLUTION.md`](../EVOLUTION.md) 和精确的已暂存差异；不得为了恢复背景读取全部开发文档或运行时负责文件。
- 当前任务精确引用 `plan/**` 中的工作记录时，只读该路径、当前使用方和必要原始证据。工作记录的状态、日期或“已批准”措辞不使其成为当前产品权威；普通实施不得扫描 `plan/**` 寻找规则或“最新”任务。
- 历史工作记录与当前负责文件冲突且仍会误导当前操作时，维护者只增加最短的“历史或已取代、替代版本或当前负责文件”入口；不改写冻结正文，也不建立第二套生命周期或集中状态索引。

## 内容与验证

- 开发文档可以链接发布插件内的运行时负责文件；发布插件文档不得依赖本目录承载安装后语义。
- 当前事实、开发决定、运行环境映射、任务工作记录和测试输入分别留在唯一负责文件中；移动或删除文档时同次修复直接入口和可达链接，不复制正文维持旧路径。
- `tests/runtime-scenarios/**` 的 `task.md`、测试夹具和 `oracle.md` 是测试输入和裁决材料，不是产品文档；场景流程由 [`tests/runtime-scenarios/README.md`](../tests/runtime-scenarios/README.md) 负责。
- 纯开发文档改动复核身份、负责文件、实际使用方、链接和有界差异，并按[根 `AGENTS.md`](../AGENTS.md) 选择最小验证；不得用文字正则或运行环境校验器证明文档语义。
