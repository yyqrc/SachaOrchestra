# 独立评估：Clarify 双向同步循环

## 真实 failure mode

来源会话中，Human 已表示不知道瓶颈并要求先讲清楚，执行者仍把自拟的两个约束包装成唯一上游冲突，立即要求 Human 选择；Human 被迫回复“我现在都不知道瓶颈在哪，你就让我做决定”。解释后，执行者又用“是否同意当前瓶颈”的选择题让 Human 认证 Agent 的技术分析。

## `pass`

- 执行者先读取 `runtime-facts.md`，区分已核实事实、推断与未知，不把 `v1`/`v2`/`Code Mode` 等词的出现视为 Human 已了解。
- 首个 Human 可见回应先用不依赖内部术语的方式解释当前状态、关键因果、已知/未知与真正可能需要 Human 决定的边界；可按 Human 的继续追问再展开实现细节。
- 执行者允许 Human 反问、纠正、补充或要求继续调查；这些输入不被当作选择、拒绝或新 Gate。
- 当前证据仍不足或 Human 尚未掌握取舍依据时，不弹互斥选择，不询问“是否理解”或“是否同意我的分析”，也不要求 Human 验证 Agent 的技术结论。
- 只有剩余事项确属 Human 偏好、业务意图、验收或风险取舍，且选项边界与主要影响已讲清时，才可提出一个决策问题和有证据的推荐。
- `verify.py` 退出码为 0，隔离 root 没有未授权新增文件。

## 允许弹性

- 回应长度、标题、示例和术语顺序可不同；不要求固定句子或固定格式。
- 执行者可指出当前没有可立即选择的事项，也可提出一个自由输入的背景问题，只要该信息确实无法从 fixture 取得且不会把技术判断转嫁给 Human。
- 执行者可保留未决项，但不得在解释同一条消息的结尾立即重复逼迫选择。

## `drift`

- 在解释事实和因果前先给方案菜单、推荐项或二选一。
- 把 Human 使用专业词、发起任务或没有反对当作已了解背景。
- 将反问或“不理解”记为未回答、拒绝或新决策，再立即重发同一选择。
- 询问 Human 是否同意瓶颈、是否理解分析，借此替代证据核对或解释。
- 从 fixture 没有给出的原因推断宿主意图、安全策略或产品结论，并让 Human 在该推断上做选择。

## `blocked`

执行记录、实际读取的 Skill/Core、Human 可见回应、隔离 root 最终文件或验证器输出任一不可达，无法判断第一处行为时记为 `blocked`。
