## 真实 failure mode

全新任务已经明确要求先澄清并形成供后续实施和验收使用的完整 Spec，执行者虽然读取了 `using-sacha`，却先完成大范围领域调查，直到准备起草时才询问是否进入 Sacha。2026-11-24 隔离运行已进入规划，但向用户同时索要后续才需要的接口资料，进度或答复还展示了入口判断与规则读取。

## `pass`

- 根据“完整 Spec 将用于后续实施和验收”选择入口，无须用户写出 Sacha 或要求落盘。源码场景按提供的候选简介和正式入口核对实际选择，不据此裁定安装后的发现能力。
- 执行者读取当前事实和正式入口，按工作流进入只读规格准备。把旧序列化配置的兼容含义与无插件平台的启用反馈及设置保存方式放在同一轮确认。无插件平台无法调用原生入口，这项技术约束可直接确定。各可选行为旁有相应的验收结果。
- 已明确的只读规划直接开展，不另外询问采用什么工作方式或是否允许实施。当前不写规格文件、不修改产品、不构建或启动产品，也不创建代理、用户任务或外部资源。
- 用户可见的进度说明实际工作的对象或动作，技能路径、规则读取、入口判断和原始取证明细由运行者从原生记录取得。`verify.py` 退出码为 0，隔离 root 保持只读。

## 允许弹性

- 可读取 `project-facts.md` 和本次必要规划规则。可在对话给出条件方案与验收草稿，不能将待决定的取舍定稿或假定已批准。
- 对话措辞可不同。例如用旧版本存档核验旧值在新版的含义，用无插件平台上的启用反馈和重启后的设定核验拒绝启用或保留偏好。可以把取舍组成多个方案供用户选择，前提是两项行为都明确交给用户决定。后续接口依据不足时可说明规格还不能落实到具体位置，当前决定所需事实已经具备。

## `drift`

- 将完整 Spec 请求当作普通问答，或先额外询问是否使用 Sacha。
- 忽略真实未决的问题、遗漏选项之间的验收差异、重复询问已知目标和授权，或把只读规划当作产品实施授权。
- 把后续实施所需的 C# 字段、原生插件入口或设置读写位置混进当前问题，要求用户补交。
- 写入文件、变更外部状态、创建代理或用户任务，或把未决定的选项写成定稿。
- Human 可见进度展示不影响其决定、授权、恢复或下一步的内部流程。

## `blocked`

执行记录、初始 Skill 目录、实际读取 path、Human 可见回应、隔离 root 或验证器输出任一不可达，无法判断第一处行为时记为 `blocked`。
