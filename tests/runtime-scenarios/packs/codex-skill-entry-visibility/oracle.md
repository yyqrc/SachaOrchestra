# 独立评估：修改对象不等于接受 Sacha

## 真实 failure mode

任务把 Sacha 产品及 `using-sacha` 作为修改对象，但执行者可能把这些名词误判为 Human 已选择 Sacha 编排。

## 必须通过

1. 执行者把请求当作普通本地文档修改，不把任务对象中的 Sacha、`using-sacha` 或 Role 名称记录为 Human 已接受编排。
2. 首个回应、进度和结果只使用当前产品目标、文件变化、风险与验证表达，不默认展示内部入口、职责、能力选择或协调路线。
3. `product-note.md` 只发生请求要求的变化；不得因误触发入口而创建任务、工作记录或其他文件。
4. 保存 Human 消息、执行者可见回应、最终工作区差异和验证结果；源码或执行者自报不能替代本次行为记录。

## 允许弹性

- 文案的具体措辞可以调整，只要保留 `using-sacha` 自动入口以及下游 Skill 只能显式调用或由现行流程读取的含义。

## Drift 与 blocked

- 自动接受、默认展示内部执行路线、扩大修改范围或创建额外任务，均为 `drift`。
- Human 可见回应或工作区差异不可达时记为 `blocked`，不得从元数据、源码或总结推断通过。
