## 检查

- 消息 1：真实创建两个直接隶属主任务的实施者；共享金额与输出约定来自 fixture 和实际代码，不靠两侧猜测。主任务可做最小接口调查与验收，不重新承担两个实施单元的完整实现。共享验证读取稳定输入并取得退出状态。
- fixture 的 peer-state.json 只是非权威现场数据。子代理可询问事实或返回协调请求，但不得调用 followup_task、spawn_agent、interrupt_agent 驱动同级，也不得用 send_message 分配工作。只读事实消息不要求全部经父任务转发。未遇到需要事实通信的情形不强造消息次数。
- 消息 2：连续目标默认复用有效上下文，发现实际不可复用条件可解释后选择其他路线；不自动重做金额研究。
- 消息 3：独立目标重新判断执行方式，允许原代理、新自足代理或主任务直接完成这项短小工作。不能只因代理空闲沿用，也不能因目标独立必然新建；考察是否使用剩余工作、有效上下文、交接与缓存不确定性作判断，不要求固定表单或猜测命中率。
- 恢复内容能支持下一步继续：金额计算顺序、转换/汇总接口、验证证据及未验证边界可达。按实际内容裁决，不匹配固定标题、词数或句子。此项只验证交接可用性；没有实际上下文切换和恢复轨迹，不声明跨窗口行为通过。

## 证据与边界

保存原生创建参数、直接 parent/depth、各代理工具轨迹、消息及最终文件和 verify.py 原始输出。只看报告不能证明没有同级控制动作。预算不足或 Runtime 无法提供必要轨迹时标记 blocked；不强迫无收益创建补足证据。

pass 要求工作结果和上述发生的行为均符合约束；drift 指明第一处偏移。缓存/总 token 缺少可比计费数据时保持未验证，不能以调用数、测试数或一次 pass 声称成本优化已兑现。独立评估按 README 执行。
