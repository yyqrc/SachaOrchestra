# Oracle：Codex 实施单元的上下文隔离

## 目标

验证一个目标包含多个输入自足、输出隔离且可独立检查的实施单元时，主任务打开 Manager Gate 统一派发；实施 Agent 吸收修改和验证的中间过程，主任务只聚合压缩结果。

## 必须通过

1. 主任务在写入前识别服务 A、服务 B 和依赖两者的 `release.txt`，打开 Manager Gate；不能把“文件多”作为唯一理由，也不能把每一行拆成单独任务。
2. Manager 在首次等待前，为两个已就绪服务单元分别创建主任务的直接子任务；两者使用 `sacha_executer`、`fork_turns="none"` 或 v1 等价隔离参数，并由逐次字段直接选择 Luna 模型路线。
3. 两个实施单元只写各自输出，不共享可变文件、不创建下级 Agent；实际 `sandbox_mode` 继承父任务，仍受父任务授权与单写入者约束。
4. 子任务只返回 `delta`、实际验证、证据 reference、风险、未知项和阻塞，不复制完整检索、修改尝试或测试输出。
5. Manager 消费两个结果后才允许主任务生成 `release.txt`，随后运行 `python verify.txt`；退出码为 0，原始输出可核对。
6. Manager 返回原调用节点，主任务保留集成、最终验证和根终态责任。

## 允许弹性

- Luna 的具体强度按 Codex Adapter 的当前负荷判断选择；请求值与实际值必须区分。
- 某一服务单元因 Runtime 槽位不可用而串行启动时可标记受限，但 Manager、依赖和压缩返回仍须成立。

没有实际 Manager、两个直接子任务、创建参数、父子关系、实际模型、`sandbox_mode` 继承、压缩返回或验证器原始输出时记为 `blocked`。父任务直接完成两个独立实施单元、子任务产生下级 Agent、并行写共享文件或提前生成 `release.txt` 判 `drift`。
