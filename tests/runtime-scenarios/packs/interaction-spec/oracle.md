# 裁决标准：interaction-spec

问题来源：2026-09-23 的 01a0cdf5-591d-78a3-90b3-aa336a358e85 审查与 01a0ce00-6d5b-72d0-9a59-89716d232da8 快速开发中，已有 Spec 要求遗漏；用户又多轮补充交互、删除无用入口、调整阶段比较及缓存，并发现目标显示与真实处理不同步。本例只验证这些机制，不把后续改变全图填充等新决定倒推成旧实现违规。

## 隔离与执行

规划阶段仅交付 fixture/planning 下的输入与 task.md，使用当前源码 using-sacha 入口。规划者看不到本文件、resume-task、review-task 和 fixture/review。运行者仅对已提出问题按下一节回应，保存原始问题与答复，不提前补发答案。

恢复阶段创建新隔离 root，仅复制项目源资料 project-source.md、processor.py、preview-example.html 与实际生成的 spec.md 及其明确引用的草稿；不传 project-brief、聊天或规划者总结。按 resume-task.md 用新上下文核对。

评审阶段使用第三个隔离 root，仅给 fixture/review 与 review-task.md；固定的 approved-behavior 是独立批准基线，不假装来自本次规划产物。最后由未参与前三阶段的评估者读取原始记录与产物，分别裁决设计、恢复和缺陷识别。设计/恢复通过不代表评审候选通过，也不代表原 Unity 工具已验证。

## 问题答复

- 比较方式：日常要比较处理前、仅填充、接缝后，可任意选两者；不需要滑动幕布。不要只固定输入对最终结果。
- 数据与入口：日常只载入生产者生成的完整快照；原始 EXR 看图、开发测试和快照生成留在各自负责入口。
- 资源与计算：当前只看一个通道；反复切换已看阶段时不要重新处理。512 MiB 预算内，按项目事实提出缓存设计；不另行重问采用何种编排。
- 选择与显示：选择一个对象或像素后要能看清两侧的对应关系；编号针对所选对象的边段配对，图例说明数据含义。
- 参数：默认半径 1 已确认；可以关闭填充观察接缝，范围外保留原输入。参数变化后不显示旧结果为新结果。
- 若规划者发现真实二维接口或快照 schema 缺失并询问范围：本轮只形成已有 8×1 原型的可运行窗口规格，沿用现有处理语义，不新增二维接缝算法或快照格式。2048² 仅为未来接入预算参考，真实接入取得对应资料后再确定。首轮曾暴露此输入缺口，原始提问与范围收敛须保留，不能把缩小后的证据宣称覆盖真实二维接入。
- 其他：已有项目事实自行读取；未规定且不改变上述使用结果的惯例由规划者决定，不要求穷举快捷键、色值或新增功能。

## 预期与允许弹性

1. 调查资料与先例后提出从完整输入到目标判断的使用过程，发现功能用途、输入职责、比较和计算取舍；已确认半径、生产者职责等不反复索取批准。
2. 提供能演示相关操作和不同状态的具体草稿，优先 HTML；自己实际预览或运行交互并保留证据。只有文件生成、静态截图、不可操作控件或一律相同结果不足。模拟结果明确，不冒充真实算法或宿主验证。
3. Spec 的入口、选择对象与配对粒度、阶段比较、参数到目标/处理/显示/统计关系和资源方案互相一致。可使用不同布局、命名或实现；不要求 fixture 外的产品功能，不强制所有问题都问 Human。
4. 不将 processor.py 的所有能力自动变成按钮；开发测试、快照生产与日常操作有用途依据。缓存采用任何满足已确认操作和预算的精确方案，不按关键词或指定数据结构评分。
5. 必要行为、算法/接口/字段、步骤及验证进入 Spec，不只留在草稿或聊天；恢复者可据此给出具体接入说明，无需补必要设计。草稿与 Spec 矛盾或必须猜测关键行为属于 drift。
6. 评审应识别：实际填充目标随半径变化，但覆盖图/统计仍用全部非支持区域；只更新左侧选中像素；已要求的 mip 并排根本没有实现。candidate-checks.py 通过不证明三项行为满足。三项都为既定行为实现偏差，应 Needs Fix；不以缺少浏览器/Unity 运行推迟源码可确认的问题。
7. 后续增加滑动比较属于新需求，不把原先排除该功能当作缺陷；不把所有潜在使用偏好列为阻塞。
8. 项目资料不足时应暴露具体缺口，不凭空补生产接口。按上述范围答复收敛后，评估本轮原型窗口的使用与规格完整性；真实二维接口、算法和内存性能不在通过声明内。

正式 pass 需要规划交互的原始记录、草稿操作证据、恢复结果与独立评估齐全；缺工具或必需证据为 blocked，实际偏移为 drift。分别列各阶段结果，不用部分通过合并成整体通过。
