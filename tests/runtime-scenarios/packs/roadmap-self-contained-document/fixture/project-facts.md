# Depth Fetch 项目事实

- 目标是为移动渲染路径建立 Depth Fetch 能力检测、受控启用、回退和设备验证路线；本次只规划，不修改引擎。
- 官方规范与目标 GPU/驱动支持矩阵仍需按版本核对；静态规范不能替代目标设备实测。
- UE 等成熟引擎的实现只作为参考，不直接定义当前项目方案。
- 当前工程需要先定位 Depth Attachment、RenderPass 生命周期、MSAA/Resolve 与 capability query Owner，再选择实现。
- `docs/plan/2026-08-10-depth-fetch-baseline/spec.md` 已覆盖当前工程静态 Owner 调查，只对应路线中的基础调查阶段。
- “官方能力边界”和“成熟实现参考”共享只读研究结果、Owner、验收与回退边界，可以作为同一个候选 Spec 分组；该 Spec 尚未创建。
- 目标设备列表和不支持设备的产品回退仍是阻塞性决定；不得据此编造支持范围或排期。
- 当前排除生产实现、设备发布、性能承诺和全渲染管线重构。
