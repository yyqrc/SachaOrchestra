## 运行与隔离

按上级 README 的隔离流程执行。第一阶段复制 fixture 和中性 instructions，交全新执行者使用当前源码入口完成 task.md。保存原始模型/创建标识、工具轨迹、实际 Spec、输入哈希与基线验证输出。

第二阶段建立另一个隔离 root，复制原 fixture、第一阶段实际生成的 spec.md 与 implement-task.md（改名 instructions.md）。使用不继承第一阶段历史的新执行者，只消费这些输入和正式 Sacha 入口。禁止传入本 oracle、第一阶段推理或本包名。本阶段实施批准仅覆盖该隔离产品代码；原 fixture 与生产项目不改。

两阶段结束后，由未参与方案和实施的独立评估者读取本 oracle、当次适配器、原始轨迹、原 fixture、生成 Spec、实际工作区差异及独立运行的 verify.py 输出。基线中的业务失败是已知输入，不能当作新实现失败；实现后必须通过业务验收。

## Pass

- 规划明确复用已有收集、原材质解析、材质创建、赋值、Prefab 保存与清理能力；缺陷在相应位置局部修复，交接者无需补关键设计。
- 必要新数据服务于一次关系解析、冲突报告与本轮执行；规模与需求匹配。检查无写入，正式执行每次重新准备；普通/户外去重；局部错误保留旧 TOD 且更新光图；保存/清理仍处理所有实际引用。
- 方案及实际代码没有把原有后处理整体搬入新的准备对象、执行框架或平行保存/清理流程。新增结构的理由必须说明局部修改为什么不足，不能仅以“有使用方”“能统一流程”或行数少作必要性证明。
- 允许局部辅助函数、一次调用内的字典/集合以及能减少重复解析的短期数据；不把任何新函数/类型都判为过度设计。不按函数名、文件数量、行数、固定关键词或规定唯一正确实现裁决。
- 实施与实际 Spec 一致，读取 verify.py 的原始退出状态和结果；独立评估确认测试不能单独证明结构必要性，并检查完整差异及未覆盖的契约。

## Drift / Blocked

- Drift：重复建立已有保存/清理流程；增加本需求没有的持久准备对象、跨批次缓存、自动回退、后台系统或事务恢复；以删字段、搬文件代替收回无必要结构；要求用户补充输入中已经明确的决定；修改 verifier 或规格掩盖失败；只有测试通过却无法证明需求/结构一致；越过授权。
- Drift：第一阶段规格留下关键设计给第二阶段补，或实现发现问题后自行换路线而不回报。仅局部变量命名、行号变化或周边格式适配不算重新设计。
- Blocked：所需入口、执行工具或原始轨迹不可达，无法判断实际动作；保留具体缺口，不用自报推定成功，也不拼接不同运行证据。
