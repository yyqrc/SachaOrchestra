# 独立判定与重放

这是开发侧合并评审案例，沿用 Runtime 场景的 `task / fixture / oracle` 输入隔离方式，不进入 Runtime 场景包或运行时 Manager/Planner 流程。

来源：2026-10-10 的实际合并回退链。Git 对象 `469ea11` 的父为 `73636f8`、`8734c74`，共同祖先为 `96bf4cd`。原始 remerge diff 显示，冲突处理恢复了旧规则，同一受影响文件还出现冲突标记外的语义回退；初轮检查后，用户补问才发现其余回退。产品合同随后已修复，本案例不声称再次复发。`b34aea6` 外部材料确认过宽是独立新增缺陷，未纳入本案例。

输入从这四个对象提取 Workflow 的运行原则、角色/Gate、动态路由与重试段，以及 Artifact 的最小记录和 Spec 标准。为同时检查合法新增，将稍后 `c6a9e2c` 在 Artifact 中新增的三段文件变更交付要求原样叠加到 incoming/result；这是明确的隔离组合，不冒充历史某次完整合并。逐段来源与 SHA-256 在 fixture 的 provenance.json；重放不依赖源仓库 Git 对象。

## 重放入口

在仓库根执行（`<run>` 必须不存在）：

```powershell
python -B tests/development-scenarios/merge-review/replay.py --output .temp/development-scenarios/<run>
```

脚本只复制输入并运行 `git diff --no-index`、`git merge-file --diff3 -p`，保存命令、退出码、stdout/stderr 和输入摘要；差异退出码 1 与 merge-file 正数冲突数是原始工具结果，不作语义 pass。已有输出目录会拒绝覆盖。脚本不初始化仓库、不创建分支或提交，不修改 fixture。

以 `fork_turns="none"` 启动执行评审的代理，只给输出 root 内的 instructions.md、input、comparisons，以及本次待验证评审 Skill 及其直接开发规则；不提供本文件、包名、既往结论或修复。保留实际工具调用及输出、最终答复和输入前后哈希。执行者结束后，启动未参与实施的独立评估者，提供本文件、原始输入/比较、执行者原生轨迹和答复；按下面标准判定。不得把实施者自检或脚本成功当独立行为通过。

## 判定标准

执行者须在用户补漏前给出阻塞结论，并以实际行为及原始位置说明：

- result 重新要求实施/探索前先尝试拆分，能拆出两个单元便打开 Manager；main 已改为按真实协调需要判断。原样保留这段会恢复强制拆分，该回退位于本案例自动比较的冲突区外，必须与冲突区一起发现。
- result 的环境不可用要求耗尽安全替代，丢失 main 对已知可用、同目标、新证据/可检验假设及无合法下一步停止的限制。只清冲突标记不能通过。
- result 弱化有 Spec 时 Executor 不得自主补必要设计的边界，与 main 的执行界定及 Artifact 中精确 Spec 的直接消费者关系冲突；必须保留 main 的有/无 Spec 区分。
- main 的局部修改、设计范围与实际 Reviewer/Manager 条件不能被旧段落覆盖。可合并描述同一回退链，不要求逐句枚举。仅追最后一个新增或把整个 incoming 删除，都不能通过。
- incoming/result 在 Artifact 中的文件变化核对、失败/超时副作用、实际路径交付是独立有效新增，应保留；不得因来源较旧而整侧丢弃。该新增是本案例批准保留项，不评估其后来精简后的表述。

`pass`：上述行为均有直接依据，范围有界，并明确保留合法新增。允许不同组织顺序、术语及合并问题描述。`drift`：遗漏关键回退、仅冲突标记检查、只查最后一个提交、整侧替换或虚报通过。`blocked`：真实输入或必要原生轨迹缺失导致不能裁决。附带发现只有改变当前结论时才展开。

每次保存独立裁决及首处偏移。失败运行保留，不覆盖后重跑掩盖；修订后用新的隔离 root。通过仅证明此组合案例，不证明未来真实合并或安装后的 Runtime 已正确。
