# Sacha 简化审计

## 功能

从明确范围内找出少量有直接证据的简化项，区分可以直接清理的重复实现与需要用户重新决定的产品能力。

## 输入与首查

1. 要求一个明确子系统、路径、机制或用户指定的横切主题；范围不清时停止，不默认扫描全仓或历史任务目录。
2. 先读[项目规则](../../../AGENTS.md)，再读取当前定义、实际使用方和真实发布或 Runtime 路径。涉及产品入口、Role/Skill 职责时读取 [`PLUGIN_DESIGN.md`](../../../PLUGIN_DESIGN.md)，涉及术语时读取 [`docs/CONTEXT.md`](../../../docs/CONTEXT.md)。
3. 只有当前定义无法解释机制或准确的替代关系时，才查询历史 Artifact 和 rollout；不把旧方案当作当前依据。

## 动作顺序

1. 为每个候选列出生产或发布使用方、测试或文档使用方，以及尚未确认的使用方；读取调用点、加载路径和生成来源，不能只凭名称、搜索零命中或静态工具报告认定无人使用。
2. 优先调查重复表达同一事实的 Core/Skill/Adapter 判断、无人直接使用的字段或状态、已被当前定义完整替代的副本、只保护未使用 API 的守卫，以及不改变下一步的模板、Hash、兼容层和校验器。
3. 对每个候选说明当前成本、删除或折叠后的净减少、保留的行为、失去的能力、受影响的使用方、验证方式和翻转条件。只把复杂度移动到包装层、脚本或新的定义位置不构成简化。
4. 如果生产使用方、持久或兼容义务、已确认的产品决定仍然成立，则将其列为需要用户决定的产品候选；现有证据不足以推翻保留理由时，拒绝该候选。
5. 只有代码、配置、schema、持久化或线格式、文档、测试和兼容行为都不再使用旧内容，且保留理由已经迁入当前定义时，才算完整替代；否则保留并说明部分替代关系。

## 输出

- 按“可直接清理 / 需要产品决定 / 保留 / 证据不足”分类，说明定义位置、实际使用方、证据、净删除、风险和最小验证范围。
- 报告已调查范围与刻意排除范围；少量强候选优先于大量薄弱猜测。

## 停止与禁止边界

- 本 Skill 只读，不修改、删除、重构、发版或创建新的产品机制；用户明确要求实施后，按普通开发范围重新读取当前定义和授权。
- 不因对称、形式统一、文件长度或“更完整”提出新抽象；不把测试或历史文档的存在自动当作生产需求。
- 候选会改变入口、节点、职责、授权、持久数据或验收时停止清理结论，明确交给用户决定。
