# Sacha 简化审计

## 功能

把宽泛的“简化 Sacha”目标收敛为少量有 Owner、消费者和净删除证据的候选，区分可直接清理的重复实现与需要 Human 重新决定的产品能力。

## 输入与首查

1. 要求一个明确子系统、path、机制或 Human 指定的横切主题；缺少 Scope 时停止，不默认扫描全仓或历史任务目录。
2. 先读[项目规则](../../../AGENTS.md)，再读取目标当前 Owner、直接消费者和真实发布/Runtime 路径。涉及产品入口、Role/Skill 职责时读取 [`PLUGIN_DESIGN.md`](../../../PLUGIN_DESIGN.md)，涉及术语时读取 [`docs/CONTEXT.md`](../../../docs/CONTEXT.md)。
3. 历史 Artifact 和 rollout 只在现行 Owner 无法解释机制或精确取代关系时查询，不把旧方案当当前权威。

## 动作顺序

1. 为候选列出生产或发布消费者、测试/文档消费者和不确定消费者；读取调用点、加载路径和生成来源，不能以名称、搜索零命中或静态工具自报单独证明无消费者。
2. 优先调查镜像同一事实的 Core/Skill/Adapter 判断、无直接消费者的字段或状态、已被现行 Owner 完整取代的副本、只保护未使用 API 的守卫，以及没有改变下一步的模板、Hash、兼容层和校验器。
3. 对每个候选说明当前成本、删除/折叠后的净减少、保留的行为、失去的能力、直接消费者变化、验证方式和翻转条件。只把复杂度移动到包装层、脚本或新 Owner 不构成简化。
4. 当前生产消费者、持久/兼容义务或已确认产品决定仍成立时，降级为需要 Human 决定的产品候选；证据不能击败现行理由时拒绝候选。
5. 旧内容只有在代码、配置、schema、持久化/线格式、文档、测试和兼容行为均不再消费，且唯一理由已迁入现行 Owner 时才算完整取代；否则保留并说明部分取代关系。

## 输出

- 按“可直接清理 / 需要产品决定 / 保留 / 证据不足”分类，给出 Owner、消费者、证据、净删除、风险和最窄验证。
- 报告已调查范围与刻意排除范围；少量强候选优先于大量薄弱猜测。

## 停止与禁止边界

- 本 Skill 只读，不修改、删除、重构、发版或创建新的产品机制；Human 明确要求实施后按普通开发 Scope 重新读取 Owner 和授权。
- 不因对称、形式统一、文件长度或“更完整”提出新抽象；不把测试或历史文档的存在自动当作生产需求。
- 候选会改变入口、节点、职责、授权、持久数据或验收时停止清理结论，明确提交 Human 决定。
