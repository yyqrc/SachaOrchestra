# Sacha 简化审计

只读查找明确范围内重复、已被替代或成本过高的机制，区分可折叠的副本与需要重新决定的产品能力。

## 调查

1. 从具名路径、机制或横切目标确定范围；能从当前任务确认的自行确定，缺少会改变范围的信息时才问。按[根规则](../../../AGENTS.md)读取当前定义、实际使用方和必要入口，不默认扫描全仓或历史。
2. 核对生产、发布、测试与文档的直接使用方及加载来源；名称、零搜索命中和静态工具提示不足以证明无人使用。只有当前来源不能解释替代关系时查询具名历史。
3. 重点检查重复判断、未被消费的字段或模板、无收益的 Hash/包装层，以及旧机制是否已被完整替代；只处理会改变当前决定的项目，不为了对称或形式增加机制。
4. 对候选说明真实成本、保留的行为、删除后失去的能力、实际使用方与最小验证。复杂度只转移到另一个包装或文件不算精简。
5. 有生产使用、持久格式或兼容义务时，说明需要用户决定的影响；无法证明可替代时保留。认定完整替代前核对仍有效的代码、接口、文档和测试，不以保留测试本身反推生产需求。

## 交付

给出少量有证据的“可清理、需要决定、保留、证据不足”候选，说明定义位置、差异、风险和翻转条件。只读调查不直接删除、修改或发版；用户要求实施后，按已确认范围和当前定义继续，不新增审计状态、评分表或专用流程。
