# Sacha 插件评审

只读审查明确差异，找出会导致错误交付的产品、实现、发布可达或证据问题；不修复、不发布，也不替代运行时独立评审。

## 输入

- 使用用户指定的 commit、range、工作区或暂存差异建立基线；远端只在比较对象或发布范围确实涉及它时核对。输入变化时更新受影响范围，不重新索取未改变的批准。
- 按[根规则](../../../AGENTS.md)读取当前负责文件和直接使用方；涉及用户可读规则或文档时使用[文档治理](../sacha-doc-governance/SKILL.md)。历史仅在会改变结论的具体缺口需要时查询。

## 检查

1. 核对差异是否在既有职责内；实际改变入口、节点、职责或负责位置时，检查批准与设计到使用方的同步，不因读取新事实就认定越权。
2. 对改变的接口追踪声明、实现和实际消费者，按影响核对失败、取消、所有权、清理、恢复和持久化。新增公共能力须有真实使用方与产品依据。
3. 涉及限制、拒绝或授权时，追到最终副作用及可能绕过的真实入口；对模型或用户可见内容检查实际提示、数据结构、结果和诊断，不以关键词判断语义。
4. 发布内容核对部署 root 与引用；纯开发内容不无条件检查安装。验证应命中实际入口，代码测试、结构、包与运行证据分别判断；关键禁止行为需要对应真实入口的负例。
5. 复用仍有效的原始证据，只补会改变结论的缺口。按根规则的触发条件判断是否需要运行场景，未触发项目不自动成为后续验证任务。

## 结果

- 每个问题说明准确位置、影响和直接证据；关键缺陷阻塞，非阻塞项可 Accepted with follow-up。覆盖范围与限制如实说明，不将实现者自检当作独立结论。
- 必需检查已能形成判断、没有具体的新证据缺口时结束。运行时 Reviewer 的 Baseline、Outcome 与返回仍由发布插件的相应合同负责，不建立第二套流程。
- 不修改交付文件、提交、安装、创建任务或操作外部资源。
