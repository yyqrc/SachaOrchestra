# Sacha 文档治理

## 功能

在明确 Scope 内按文档身份、唯一 Owner、直接消费者和发布可达边界治理 Sacha 文本；提高信息密度时保留会改变判断或行动的完整命题，并把历史材料与现行权威分开。

## 输入与首查

1. 要求一个目标 path、差异或 Human 明确指定的有界子树；缺少 Scope 时停止，不推导全仓审计。
2. 先读[项目规则](../../../AGENTS.md)。目标位于 `docs/**` 时再读[开发文档规则](../../../docs/AGENTS.md)和适用的 [`CONTEXT.md`](../../../docs/CONTEXT.md) 条目；目标位于 `plugins/sacha-orchestra/**` 时读取插件内唯一 Runtime Owner 与直接消费者。
3. 只有入口、节点、连线、Role/Skill 职责或 Owner 转移可能变化时读取 [`PLUGIN_DESIGN.md`](../../../PLUGIN_DESIGN.md)；普通局部文本不借此扩大 Scope。

## 动作顺序

1. 先按 path 判定开发控制面、发布 Runtime、任务 Artifact 或测试输入；一份文档只保留一种身份。发布 Runtime 的本地引用必须留在部署 manifest 解析出的发布 root 内。
2. 按直接消费者区分 Human 可读叙述、正式标识、代码与机器合同。面向 Human 的流程和维护叙述使用中文；产品、Role、Skill、Runtime、API、字段、枚举、状态和 Owner 已定义的硬术语按原标识保留，中文可能产生歧义时首次写作“中文（英文原词）”。不得用关键词扫描代替语义判断。
3. 确定每项事实的唯一 Owner 和当前直接消费者。当前 Owner 能承载时只修改该处，其他位置改为最短映射或链接，不新建平行说明。
4. 改写前枚举保留命题中的主体、条件、动作、顺序、规范强度、停止/恢复、例外、Owner、消费者、失败、授权和证据边界；只有这些事实全部保留且含义唯一时才压缩。
5. 对会话视角、评审编舞、临时计划编号、不可达草稿引用和控制流叙述使用一个判据：当前仓库读者不依赖对话、PR 线程或未提交草稿，能否解析每个引用并验证每个事实。不能时把真实事实改写为当前状态并删除过程叙述；没有事实的过程文本直接删除。
6. 不把现行机制的历史、生成投影或测试清单手写进 Owner。生成内容修改其来源；源码、发布包/缓存、Runtime 和 Human 验收分别报告，不互相替代。
7. 移动、删除或标记取代前核对入链和完整取代关系。历史 Artifact 只在仍会误导当前操作时增加最短“历史/已取代、当前 Owner”入口，不现代化冻结正文。
8. 复核相邻文本是否依赖同一语义；只处理直接消费者，不扩成无消费者的语料库清理。

## 输出

- 报告 Scope、文档身份、唯一 Owner、直接消费者、完成的迁移/精简、刻意保留、冲突或未验证边界。
- 只读请求只交付发现；获授权的修改使用真实统一 diff，并运行目标身份对应的最窄验证。

## 停止与禁止边界

- 文本变化会改变产品入口、流程、Role/Skill 职责、授权、验收或破坏性边界时停止写入并交 Human 确认，不把语义变化伪装成文案整理。
- 不用关键词、固定句子、段落顺序或字数证明语义；不因“更完整”增加规则、Artifact、字段或校验器。
- 本 Skill 不执行项目文档生成、Runtime 场景、发布、安装、Git 写入或外部动作。
