# Sacha 文档治理

在明确范围内整理规则、技能与文档，确认读者、负责位置和实际可达性；不改变未获批准的产品行为。

## 开始

- 先从用户目标、路径或差异确定范围；能从上下文明确的自行确定，只有歧义会改变产物或范围时才提问。
- 读取[根规则](../../../AGENTS.md)中的负责位置与读取入口；docs 内容再读 docs/AGENTS.md，术语查 CONTEXT.md 相关项，入口或职责变化查 PLUGIN_DESIGN.md。技能或适配器正文使用[文本参考](references/skill-and-adapter-text.md)。

## 整理与核对

1. 按用途区分开发文档、发布内容、任务记录和测试输入；根据实际使用方确认唯一负责位置及读取时机。安装后必需内容须在发布 root 内可达。
2. 面向读者用自然中文，保留影响理解、授权、恢复和验收的事实及精确技术身份。代码与机器合同不靠翻译或关键词判断，表达原则沿用全局规则。
3. 区分纯表达、重复折叠和行为调整。核对受影响要求的条件、动作、依赖、结果和例外；难以核对的合并才逐条列对应，不机械枚举所有字段。未经批准的产品、授权或验收变化不作为文案修改写入。
4. 删除不承担独立判断的重复解释；完整定义留在负责文件，使用方保留引用与自身映射。核对直接相邻内容，不扩成全语料清理。
5. 将依赖会话、临时编号或不可达草稿的现行叙述改为有来源的当前事实；历史记录按根规则处理。生成内容修改其来源，不手写第二份生成状态或验证清单。
6. 复核实际使用方、链接与剩余歧义，按根规则选择最小验证。无法确认的内容保留并说明，其他已明确且获授权的部分继续。

只读请求报告发现；修改请求交付实际差异、行为影响、验证与未决项。产品范围变化按根规则取得对应决定，已有批准不重复索取；本技能不执行发布、安装、Git、运行场景或项目文档生成。
