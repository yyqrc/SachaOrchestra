# Coordination Contract（协调合同）

> 状态：规范性 Core 协调合同

## 1. 范围与 Owner

本文负责工作包、依赖、就绪、派发、等待、取消、结果消费及 Owner 转移。术语见[术语合同](terminology-contract.md)，Gate 与生命周期由 [Workflow Contract](workflow-contract.md) 决定，用户交互与记录分别遵循 [Human Interaction Contract](human-interaction-contract.md) 和 [Artifact Protocol](artifact-protocol.md)。
无委派、跨上下文 Owner 转移/返回或恢复消费者时不加载。

Manager 在主任务内处理候选并返回调用节点；Gate 关闭的单个有界单元由主任务直接管理，沿用同一规则。普通执行、迁移后的执行和 Explore 共用下述闭环。主任务保留 Role、Scope、授权、派发、集成和根终态责任；集成须有写入授权，正式裁决保留 Reviewer 来源独立性。

## 2. 评估、拆分、依赖与就绪判定

按可独立交付和检查的结果划分工作包，明确目标、Scope、授权、输入、Owner、输出边界和验证入口，建立依赖波次。共享接口或初始化约定未定时，先最小调查或合并耦合部分；下游只推进不依赖该前提的工作。

派发前核对风险与难度、上下文、直接验证、返工成本及独立性，形成 Adapter 所需路由要求；权限、破坏性后果和持久数据按实际影响判断。缺少会改变选择的事实时暂停该单元，已有判断只在相关输入、范围、依赖或安全状态变化时重评，不要求固定表单。

主任务侧重方案、协调、授权与冲突处理、验收；自足的实施、集成和验证优先委派，确定性批处理复用脚本。上下文充分且委派成本更高的短小动作由主任务完成；难以隔离、检查或仍需共同推理的部分先保留在调用节点。后续成为独立工作包时重评，串行写入也可委派，不按文件数、型号、时长或代理数量强行拆分。

执行就绪（`execution-ready`）：Scope/验收冻结，输入与边界自足，授权和依赖满足，可独立交付，完成检查与验证责任明确。实施者做局部检查，主任务安排共享验证；共享验证不阻止隔离的实施并行。
研究就绪（`research-ready`）：当前决定、消费者、问题、查询范围、所需证据和停止条件明确，输入自足、依赖满足，默认只读；可先于实施范围冻结。Core 形成路由要求，Adapter 映射模型与参数；有界不等于低难度。

证据足以支持当前决定时交付；继续调查只针对会改变结论的剩余未知项及直接依赖。问题无法收敛或需越过查询范围时，返回已有事实、具体缺口和协调请求。未来阶段仅保留候选引用，除非已构成当前决定的必要依赖。

内部未知项由实施者解决；改变跨单元接口、共享状态、初始化或验证前提时交主任务处理，独立工作继续。

独立工作默认新建代理。连续补证、返修或实施在目标与完成条件连续、授权相容、原决定/改动/证据仍参与本轮判断且收益大于历史负担时，优先复用原代理与模型。目标、写入范围或验收明显变化时重判；同工程、领域、文件、空闲或缓存本身不足以支持复用，也不按消息数或上下文阈值自动换代理。新建仅交付自足输入与有效证据，保持单写入者；传输和容量由 Adapter 处理。

## 3. 派发、等待、取消与单写入者

派发消息包含目标、允许范围、完成检查、停止及协调请求条件；研究另给问题、查询范围与预期证据，依赖或并发另给隔离边界。工作 root 与默认目录或 Skill 目录不同时，交付 root、规则、任务输入的精确入口及允许的外部 Skill/reference；接收方先读指定规则，避免从错误目录推导规则或搜索任务输入。

Adapter 支持时，同级可直接交换范围内的事实、接口说明和证据，无需主任务逐条转发或抄送；否则沿现有返回路径交付。新目标、写入归属、继续/中断调度及共享验证与验收由主任务决定，约定变化返回协调请求。

中间消息只在接收方下一步需要变化时发送：冲突、失败、授权/接口变化、依赖就绪或正在等待的结果及时交付，已知相关事实与缺陷合并发送。其他发现随结果归并；不定时催报、确认收到、广播无关提醒、重发完整结果或用中断再继续探测进度。必要披露不受消息配额限制。

已有结果按当前问题交付事实、证据版本和剩余缺口；接收方核对适用性后仅补缺口或失效部分，沿用有效依赖清单。重新评审交付本轮差异和受影响证据，复用遵循[验收合同](assurance-contract.md)。

读取先定位未知项，再取片段；批量只合并已知独立输入。已返回的有效内容直接复用；版本变化、具体疑问或影响判断的截断才补相关范围。规则与 Skill 按当前阶段加载，完整约束影响判断时读原文。持久决定、证据与恢复按 Artifact Protocol 使用现有载体，不另建定时检查点。

只读可并行；共享树中对同一文件、可变输出、生成物及公共结构的写入，以及 Git 和整体验证保持串行。隔离树、补丁或候选实现可重叠分析，由集成 Owner 串行应用。

共享可变环境同一时段仅一个操作者，可委派；其他单元继续独立工作。同环境、同产物且步骤确定的验证合并执行，固定该批输入；决定后续路线的最小检查优先，新失败交回决策者并按修复影响复验。环境操作与恢复遵循领域技能。

派发时明确局部检查、共享验证及接收者。共享编译依据实际读取的源码、生成输入、配置和依赖判定冲突；启动前确认相关写入者已冻结输入并交回改动与待验证项，无法确认独立性时等待。实施者可交回后结束回合；主任务在输入稳定后安排合并检查，期间不派发修改该批输入的工作。

编译读到未完成输入时，保留原始结果、输入状态和待验范围，稳定后补验。错误归属须有证据；即使来自其他任务，也不免除本任务验证。稳定批次失败按归属返修，复用未受影响证据。

主任务对当前 Task/Scope 持续调度，每波按就绪、依赖、授权、隔离和收益选择自行执行或单层派发：

```text
评估当前波次 → 串行执行或并行派发 → 聚合本波结果 → 重算剩余依赖图 → 下一波 / 阻塞 / 耗尽
```

串行只约束当前波次，返回后重算剩余依赖并保留未完成的集成、验证。依赖耗尽、无可推进单元并交付阻塞/恢复条件、命中停止条件或进入偏差处理时结束本次调度；根任务完成仍按整体条件判断。

反复依赖外部决定、接口变化或主任务补充时，收敛接口、调整波次或合并耦合部分，复用已有成果。稳定输入上的相关缺陷合并返修，决定路线的失败先处理。转移归属前确认旧写入者状态；影响 Scope、授权或验收才交 Human 决定。

派发后先推进独立且不冲突的工作。目标已启动、主任务消费其结果、下一转换依赖该结果且无其他就绪工作时，按当前 Task/Scope 与隔离边界等待。正常消费完成回传，保底活性查询按 Adapter；收到新事实后重算依赖。无结果消费者的 Owner 转移不等待。

首次创建使用 Adapter 完整映射的参数，不自行以通用 Role、默认继承或局部参数替代；参数不完整进入偏差处理。等待、取消与停止证明由 Adapter 执行，取消后不得留活跃写入者；超时不触发重复创建或流程转换。

返回消费者所需的结果/`delta`、已验证事实、实际验证、reference、风险、未知项、阻塞和协调请求，披露失败、未验证及范围/授权偏差。完整检索、源码和日志留在原始记录，按当前决定需要给精确片段；仅按 Artifact Protocol 保存有消费者的记录。消费与去重按第 6 节。

父任务核验关键原始证据及适用性，不重做仍由代理负责的完整调查。冲突、缺依赖或影响不明时优先具体补查；接管须明确责任转移与原代理停止范围。正式独立复核遵循验收合同。

## 4. Explore 研究

Explore 先用当前事实，再按第 1–3 节协调研究；归并事实、冲突、未验证项和 reference 后返回调用节点，活跃 Planner 判断是否足以冻结 Spec。显式 Explore 仅授权只读协调，不接受完整 Sacha，也不授权写入、冻结方案/验收、Review 或外部动作；需要这些动作、新 Scope/方案或新授权时，停止相关动作并返回 Planner/Human。

## 5. Executor 任务迁移

Workflow 确认明确迁移批准及执行任务迁移前提后，来源停止实施和写入派发，只查询/创建目标并交付最小 Handoff、reference。以 Task/Scope 修订号、批准 Spec reference 和工作流转移消歧，保留首次创建的原生标识；重试、重复批准或恢复复用唯一目标，不建跨会话注册表。

唯一目标取得项目规则、批准 Spec、必要 Artifact/证据及传输缺失的最小 Handoff 后，接管主任务和剩余 Execute、Review/返修、收尾，沿用通用 Gate 与协调规则。来源交付原生任务 reference 后结束，不等待返回；不复制完整对话，委派 Agent 不取得迁移标识、Owner 或派发权。

转移前查询、创建或交付失败时，来源保留唯一 Owner 并报告恢复条件；Human 改为普通批准后才恢复实施和写入派发。转移后由目标负责恢复、失败和结果，来源不恢复 Owner；重复输入只返回既有 reference。标识或前提不可证明时停止迁移并报告偏差。

## 6. 完成、返回与偏差

Owner 保留目标、Scope、授权和完成条件。每个委派单元/Role 对同一修订只回传一次结果，消费者只消费一次；原生传输不足以消歧时才补 Task/Scope 修订号、Source/Target、Owner 或去重信息，更正使用新修订号。

Human 在另一真实任务显式调用 Feedback，授权来源有界只读调查并查询、复用或创建唯一反馈目标，不使用执行迁移前提。反馈标识包含工作区、具体目标、Owner 及 Human 已提供的来源 reference：精确匹配且活跃/可恢复的唯一目标可复用；无匹配则在本次授权内创建一个目标，无需追加确认；同标识已终止的精确重复返回 `no_op` 与既有 reference，其他已终止/过期候选不匹配。标识、状态或唯一性不明时请求消歧。
Feedback 必须交付原生目标 reference，调查代理仅补证，不接管反馈 Owner、Role 或标识。成功转移后来源结束，不等待或转述目标最终结果；目标按 Intake 重新判断，并另行核对写入及外部动作授权，继续通用流程。

同一 `payload` 兼作报告与完成回传时只发送一次，通过当前传输的完成路径交付消费者；Human 结果只呈现已消费内容，遵循 Human Interaction Contract。

根终态及结果：

- `goal_complete`：目标、Scope 和必需验证已满足；
- `goal_partial`：已授权子集完成，剩余部分明确未完成且当前目标不再继续；
- `goal_cancelled`：Human 或上游 Owner 明确取消；
- `goal_superseded`：目标被新目标替代；
- `human_decision_required`：继续需要实质方案、Scope/验收变化、新高影响授权、不可消歧 Owner 或 Human/外部恢复；Planner 提案获批且无其他阻塞时，主任务立即消费该回复并启动 Executor；
- `completion_return_blocked`：安全返回传输与替代路径均不可用；
- `external_failure`：外部系统已终止且同 Scope 安全恢复路径耗尽。

无改动但目标已满足时使用 `goal_complete`/`no_op`。其他非完成终态保留已完成范围、未完成原因、证据与恢复条件。

有返回消费者时，核对结果消费、当前传输所需标识与 Baseline，以及下一转换已启动、处于可证明的等待/用户引导或合法根终态；原生绑定的标识不重复编码。任务迁移按第 5 节核对。

偏差保留预期、实际、影响、证据、恢复/停止条件及传输缺失的标识。错误、陈旧或重复结果不产生额外写入、等待、转换或终态。环境不可用先耗尽同 Scope 安全替代；实现缺陷与补证返回原 Executor，研究失败、冲突或缺口返回调用节点，Explore 由活跃 Planner 继续核对。旧写入者停止前不另开写入者或盲目重试。
