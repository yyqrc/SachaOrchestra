# 入口规则

## 1. 范围

本文件规定如何根据当前请求判断工作方式、沿用授权及补齐未决事项。适用入口包括 `using-sacha`、用户明确调用的角色、探索、路线图、`closeout`、`document-project` 和反馈。各步骤由[工作流规则](workflow-contract.md)规定，协调见[协调规则](coordination-contract.md)，提问与交付见[交互规则](human-interaction-contract.md)。

## 2. 最小加载

默认只需常驻 `using-sacha` 的元数据。同一对话从查现状转为准备方案或实施改动时，按新请求重新判断入口，沿用仍适用的事实、决定和授权。需要澄清会改变方案或验收的行为，或需要持续探索、完整实施规格（Spec）、正式协调、独立评审、交接或恢复时，按入口技能指引读取本文件及当前步骤所需的规则。明确调用 `using-sacha` 时也按该指引读取，其他显式入口按第 4.1 节处理。

元数据已足以判断可直接处理的普通查询、定位或开发请求，在当前任务按项目规则继续。无需为了判断入口额外读取整套规则或建立工作记录。运行记录写入失败不改变入口判断。

## 3. 入口判断

- **只读探索**用于调查事实、解释、比较或厘清会改变做法的决定。明确要求交付 Spec、决定记录或草稿时，按[工作记录规则](artifact-protocol.md)和已有授权准备并保存。只读请求不授权修改项目源码、配置、资源或外部状态。用户明确要求不写文件时，在对话中交付。
- **按已确认范围实施**用于用户已授权的改动。目标、关键做法、范围和验收足够明确时直接开始，按授权完成必要验证、修正局部偏差和交付。规模、文件数或复杂度不单独决定是否需要专门规划、协调或评审。
- 影响实施的关键事实或方案仍未确定，或者用户或实际接手者需要可实施的规格时，按工作流进入探索或规划。先自行调查和比较，只向用户提出资料无法解决且会改变做法的问题。普通定位或一个局部问题能解决时，在当前任务处理。
- 继续、迭代、返修或复查已有任务时，从当前对话和可核实的工作记录恢复适用的决定、授权、工作阶段及负责方。只查仍影响当前动作的缺口。旧记录中的流程选择可以用于定位历史，但不额外确认使用 Sacha。任务链接、文件标题、规格或产品名称本身不授予写入权限。只读参考或新目标按当前请求判断。
- 尊重用户已说明的工作方式和限制。用户要求在当前任务直接处理或不委派时照做，适用的安全、单一写入者和验收要求继续生效。只提到 Sacha 或技能名称时，按请求实际目的判断。

## 4. 入口决定

- 入口判断不需要用户单独同意使用 Sacha。能在已有授权内进行的探索、准备、实施或验收直接继续。目标、范围、关键方案、验收或相关授权发生实质变化时，只重新判断受影响的工作。
- 确实缺少会改变目标、范围、关键做法或验收的决定，或缺当前动作所需的授权时，按[交互规则第 3 节](human-interaction-contract.md#3-human-决定与对话同步)询问并处理等待。追问或要求补查事实本身不批准实施。
- 每次授权只覆盖已明确的目标、范围和动作。创建独立用户任务、向指定任务发消息、安装、Git、发布、远程资源、权限和其他受控动作各自按既有规定判断。一个明确请求可以同时授权多个具体动作。

### 4.1 用户明确调用

| 请求 | 可直接继续的工作 |
| --- | --- |
| 明确调用 `using-sacha` 或要求用 Sacha | 按本文件判断工作方式及所需步骤，沿用当前请求的实际授权 |
| 明确调用 `planner`、`executor` 或 `reviewer` | 进入对应角色。规划或评审不追加实施授权，执行只处理本次已授权的范围 |
| 明确调用 `explore` | 在限定范围内只读探索。宿主允许且已有授权时可使用只读研究代理。由规划或路线图发起时，结果交回原步骤 |
| 明确要求另开任务编写 Spec | 有针对该目标的明确创建授权时，可创建对应的规划任务。新任务不继承来源任务的实施、写入或外部动作授权 |
| 明确要求 `roadmap` | 只读调查和按需探索，由 `document-project` 按项目接入配置写入路线图。编写 Spec、实施阶段或另开任务依其本次授权处理 |
| 明确要求 `document-project` | 处理该文档目标。用户明确指定的发布文档路径覆盖本次写入。其他目标按项目策略及已有授权处理 |
| 明确要求 `closeout` | 处理本次请求的 Spec 状态或存档，顺序和失败规则见[工作流规则第 5 节](workflow-contract.md#5-标记-spec-完成和写入存档) |
| 明确要求 `setup-project` | 只处理本次获准的项目配置 |
| 在另一真实任务中明确提交 `feedback` | 有界只读调查并查找唯一处理任务。沿用可核实的创建或发送授权移交一次。目标任务另行核对写入和外部动作授权 |
| 直接调用 `manager` | 由主任务按工作流判断是否需要协调 |

显式探索或规划、路线图中的探索，可以在请求允许的范围内按[工作记录规则](artifact-protocol.md)保存决定记录和独立界面草稿。保存规划材料不扩大项目实施授权。宿主 Hook 只在另有授权时准备环境，不决定入口、恢复或动作授权。
