# Using Sacha（智能入口）

## 功能

拥有 [Intake Contract](../../core/intake-contract.md) 的默认入口流程：决定保持 Direct，或在 Human 接受后把路由交给 [Workflow Contract](../../core/workflow-contract.md)。

## 输入与首查

进入本技能后，先完整读取[入口合同](../../core/intake-contract.md)，核对目标、范围、授权、验收和项目规则。只调查足以判断入口的事实。初次判断、恢复已接受的任务或事实变化后重新判断，均按该合同处理。

## 动作与输出

1. 入口合同判定保持 Direct 时，按当前任务的语言继续，无须单独汇报入口判断。
2. 需要提出 Sacha 选择时，读取[交互合同](../../core/human-interaction-contract.md)。说明两种做法对当前交付的影响、各自的成本和推荐，按入口合同提问。用户反问、要求调查或纠正前提时，按交互合同回应，再根据最新事实核对提问条件。不得用独立事实调查推迟条件已经具备的提问。
3. 确认接受时记录接受事实。接受或恢复后，按[工作流合同第 2.2 节](../../core/workflow-contract.md#22-下游-skill-读取)读取当前目标技能。需要映射传输、恢复、外部状态或当前宿主已提供的 Sacha 观测能力时，读取对应适配器。观测记录失败不改变入口结果。
4. 显式 `document-project` 按入口合同直接处理当前文档请求。

入口判断由主任务完成。拆分、派发、实施和验收交给工作流指定的负责方。Artifact 和 Handoff 沿用[术语合同](../../core/terminology-contract.md)，写入、安装、Git、发布、远程资源和高影响动作沿用各自规则与授权。
