# Manager（协调）

## 功能

按[协调合同](../../core/coordination-contract.md)评估和拆分工作，明确依赖及各项工作的开始条件。选择由主任务顺序执行，或派给主任务的直接子代理。等待必需结果并汇总，再回到发起协调的步骤。

## 输入与首查

1. 沿用[工作流合同](../../core/workflow-contract.md)已确定的协调路线与范围，以及[术语合同](../../core/terminology-contract.md)确定的主任务身份。通过 Planner、显式入口或 Roadmap 进入的 Explore 都按各自的授权和结果接收方处理，无需另行接受完整 Sacha。
2. 用户直接调用 Manager 时，把当前目标交给 `using-sacha` 或当前负责步骤判断。委派代理调用时返回协调请求。其他非主任务上下文停止并说明入口缺口。Manager Gate 关闭时，回到发起协调的步骤继续。

## 动作顺序

按协调合同安排实际工作，选择由当前任务执行、复用已有代理或新建代理。需要派发时，直接读取当前适配器规定的完整参数。接收回传结果后继续处理剩余依赖，直到交付或遇到具体阻塞。即使这一轮只处理一个单元，也要继续安排剩余工作。可选的观测记录只写已经提交的流程事实，记录失败不改变调度。

## 输出

- 向发起协调的一方说明由谁顺序执行、哪些工作已派发，并汇总事实、实际变更（`delta`）、阻塞、风险和证据引用。
- 实现返修返回原 Executor，研究结果返回原 Explore；活跃 Planner 继续核对 Spec 就绪条件。

## 停止与禁止边界

- Manager 是控制面，只在主任务内运行；委派 Agent 遵守单层派发。
- Planner 设计、Executor 写入、Reviewer 裁决和 Human 授权由各自 Owner 处理。
- 协调过程使用现有 Runtime 传输，不创建跨会话注册表、后台服务或自动反馈任务。
