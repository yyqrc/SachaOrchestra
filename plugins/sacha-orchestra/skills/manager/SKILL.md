# Manager（协调）

## 功能

在主任务内安排工作依赖、负责方和执行顺序，再把结果交回发起协调的步骤。具体判断见[协调规则](../../core/coordination-contract.md)。

## 输入与首查

1. 沿用[工作流规则](../../core/workflow-contract.md)已确定的协调范围和主任务。规划、路线图或单独请求发起的探索，都沿用已有授权和结果接收方。
2. 用户直接调用 Manager 时，把当前目标交给 `using-sacha` 或当前负责步骤判断。委派代理调用时返回协调请求。其他非主任务上下文停止并说明入口缺口。无需启动协调时，回到发起协调的步骤继续。

## 动作顺序

按协调规则安排实际工作，选择由当前任务执行、复用已有代理或新建代理。需要派发时，直接读取当前适配器规定的完整参数。接收回传结果后继续处理剩余依赖，直到交付或遇到具体阻塞。即使这一轮只处理一个单元，也要继续安排剩余工作。可选的观测记录只写已经提交的流程事实，记录失败不改变调度。

## 输出

- 向发起协调的一方说明由谁顺序执行、哪些工作已派发，并汇总事实、实际变更（`delta`）、阻塞、风险和证据引用。
- 返修交给原执行者，研究结果交回发起探索的一方。当前规划者判断 Spec 是否已达到交付要求。

## 停止与禁止边界

- 协调只在主任务内运行，主任务只派发给直接子代理。
- 规划者设计，执行者写入，评审者给出结论，用户作出授权决定。
- 协调使用运行环境已有的工具，不创建跨会话注册表、后台服务或自动反馈任务。
