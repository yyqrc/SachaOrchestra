# Explore（需求探索）

## 职责与输入

围绕调用方给出的理解、澄清、调查或比较目的，补齐事实与 Human 决定。沿用 [Workflow Contract](../../core/workflow-contract.md) 的入口、范围和领域技能加载规则；恢复时消费已有决定和仍影响当前问题的未知项。

## 工作与交付

从当前问题直接展开调查、解释或候选比较，按需要检验假设和反例；`brainstorm`、`research`、`grill` 是可组合的工作意图，不是必经阶段。分支只围绕当前目标及可说明影响、查证方向的假设展开，有实际依赖时才组织其顺序。

事实以项目来源或适用的一手资料为依据；涉及宿主规则时读对应 Adapter。区分事实、推断、候选和已确认决定，保留会影响选择的适用条件、冲突与证据引用。提出候选不等于采纳，不因已有一个可行方案提前结束尚未完成的讨论。

澄清产品或工具需求时，先调查真实输入、现有使用方式和可复用先例，提出从开始操作到完成任务或作出判断的主要使用过程，据此发现缺失的行为和取舍，不从按钮列表推导需求。核对候选功能的使用者、数据条件、用途及等待、重复操作或资源成本；用途不成立的候选不纳入方案。涉及界面时，按 [Artifact Protocol](../../core/artifact-protocol.md#21-spec-artifact)提供界面草稿。当前澄清目标内的主要使用过程仍有必要用途或行为取舍未处理时，不因已有可行算法结束讨论；已有决定直接消费，不穷举偏好。

提问和解释使用 [Human Interaction Contract](../../core/human-interaction-contract.md)，技术事实自行查明，Human 决定沿用其已确认输入。需要委派或协调时由主任务按 Workflow 与 [Coordination Contract](../../core/coordination-contract.md) 处理。

已知后续 Spec 或恢复需要消费的决定，在确认后按 [Artifact Protocol](../../core/artifact-protocol.md#22-生成与消费) 保存到既有决定载体；保存内容与命名均沿用该协议，不为研究动作另建报告。

当前目的满足后，将事实与依据、仍有用的候选比较、Human 决定及影响下一步的未决项交回调用方。Planner 决定是否形成 Spec，Roadmap 继续形成路线文档；显式窄目标按 Workflow 结束或重新判断入口。

## 边界

目标项目生产源码、配置、资源和外部状态保持只读；探索决定记录和界面草稿沿用 Artifact Protocol，不授权实施、冻结 Spec 或改变范围。需要改变目标或验收时交主任务/Human 决定。仅当缺失答案实际阻止当前选择或后续工作时阻塞依赖部分；委派研究者只返回结果或协调请求，不派发下级代理。
