# Roadmap（项目路线图）

## 功能

独立编写项目路线图。按需用 Explore 补齐事实和用户决定，说明长期目标、阶段、依赖、完成信号及各阶段对应的实施规格。通过 document-project 写入项目接入配置指定的路线图目录。

## 输入与首查

1. 只处理用户明确提出的路线图请求。明示调用的授权见[入口规则](../../core/intake-contract.md#4-入口决定)，提问和交付按[交互规则](../../core/human-interaction-contract.md)处理。
2. 先读项目规则、当前项目接入配置、项目事实、现有正式文档和相关 Spec。接入配置须给出唯一的路线图目录和文件模式。缺失时只暂停写入，继续能做的调查和正文准备，并说明 `setup-project` 需要的具体输入。沿用已有配置，不自行另选目录。
3. 更新时从用户输入或当前任务可访问的引用定位唯一文件，核对它位于配置的路线图目录。文件名和日期只供定位线索，不能用它们猜测目标。新建时按项目配置生成短而稳定的文件名，日期用首次创建日，后续更新沿用原路径。
4. 缺少会影响路线的事实、范围或决定时，按[入口授权](../../core/intake-contract.md#4-入口决定)调用 `$sacha-orchestra:explore`。该技能在同一目标内只读调查，以及按工作记录规则保存必要决定或界面草稿，再把结果交回。需要新增授权时，只暂停受影响部分。

## 动作顺序

1. 按[工作流规则的运行原则](../../core/workflow-contract.md#2-运行原则)划分阶段和主要工作。根据项目来源与用户决定明确目标、预期结果、当前状态、适用范围、排除范围和稳定约束。路线图不得自行定义项目事实或改变范围。
2. 使用 Explore 返回的已核实事实、用户决定、冲突、阻塞、未知问题和证据引用。内容能准确陈述且依赖可判断时，才组织成阶段，或将会改变路线、尚未作出的决定写入「待决定事项」。事实不足、暂时还说不清的问题，写入「待查明的问题」。不得据此编造阶段、日期或 Spec。
3. 每个阶段按项目语义写清名称、目标结果、范围、必要工作和完成信号。进入条件、依赖、风险、待查明的问题和对应的实施规格，只记录已有依据且影响阶段安排的内容。不得为填写这些内容扩大调查或设计。阶段顺序由依赖与目标结果决定。日期和工期须有实际排期依据。
4. 阶段与 Spec 可一对一。多个阶段有共同目标、负责方、验收和回退边界时，也可以归入同一个 Spec。阶段相邻本身不能作为合并依据。引用已有 Spec 的准确路径，尚未形成的只标为候选。实施方案及 `spec.md` 由规划者处理。
5. 正文必须包含「目标与预期结果」「当前状态」「路线原则」「阶段路线」「各阶段对应的实施规格」「待决定事项」「待查明的问题」「排除范围」「主要项目位置与依据」。没有事项的必需章节写「当前无」，有实质内容时再加其他章节。新建使用上述标题。更新旧路线图时，可以保留原有的「目标与完成形态」「Spec 映射」「决策前沿」或「Unknown」，并按获授权的编辑范围决定是否改名。同一主题只用一个标题。正文只写一次独立理解所需的项目事实，详细实现和证据给出可达引用。
6. 项目成员和代理都应能独立读懂路线图的目标、阶段、依赖、完成信号和 Spec 分组。正文只保留项目内容，省去 Sacha 角色、技能调用、任务 ID、适配器、交接和内部流程信息。
7. 准备正文时，按 [`document-project` 的模板规则](../document-project/SKILL.md#动作顺序)选一次模板，保留第 5 步的必需语义。按[路线图文档输入](../document-project/assets/roadmap.json)把选定的 `template_profile`、正文和写入参数交给 `document-project`。
8. 以生成器的写入和回读结果判断是否已保存。写入失败时保留完整正文及恢复条件。
9. 按[工作流规则第 4 节](../../core/workflow-contract.md#4-生命周期与-human-路由)判断是否推荐另开规划任务。已有针对该任务的创建授权时直接沿用，否则只确认创建。把路线图路径、目标和范围、已确认决定、未决项及明确的“使用 Sacha Planner”请求交给宿主适配器。

## 输出

- 先给出路线图实际或计划路径，说明已创建、已更新或尚未写入，并概括目标、主要阶段和已有的 Spec 安排。把影响阶段安排、使用或恢复的未知项、冲突和验证结果放在对应内容旁。需要核对写入状态或排障时，引用 `document-project` 返回的 `transaction`。
- 成功写入时提供可直接打开的 Roadmap path；未写入时明确标记 draft 和恢复入口。
- 另开的规划任务创建成功后，给出目标任务链接或标识，结束当前路线图任务。

## 停止与禁止边界

- Roadmap 是项目文档，不是 Artifact、Spec、任务状态、实施授权或完成证据。
- 不自动创建或执行 Spec、阶段、Issue、Ticket、分支、发布或外部资源。后续任务创建和实施的授权沿用[入口规则](../../core/intake-contract.md#4-入口决定)。
- 不从文件名、目录排序、旧任务记录或 Sacha 输出推断项目当前状态；当前状态只接受项目规则、源码、配置、正式项目文档、运行证据或 Human 决定。
- Roadmap root、文档 path 与写入授权分别沿用 Project Integration 和 document-project；root 外写入、Git、安装、发布和外部动作需要各自明确授权。
